# 11 — Decision log

Decisions made in this spec that a reader might reasonably want to
relitigate. Each states the alternative and why it lost. Workers append
here when a package changes a decision (`10-worker-brief.md`).

| id | Decision | Alternative | Why |
|---|---|---|---|
| D-01 | Keep `service_accounts` as the principal table; add columns | Rename to `principals` as datum-gate `03` does | Touches every query and every test for a cosmetic gain. The word "principal" is used in the API paths and the UI, which is where a human reads it. |
| D-02 | Fold `agents` into principals with `kind='agent'` and `parent_id` | Keep the two-level table and add scope columns to `agents` | Two tables was the reason an agent inherits its owner's whole authority (`01 §4.3`). One table with a narrowing rule gives every agent its own grant and makes delegation depth-N for free. The fold copies the parent's scope so nothing changes on migration day. |
| D-03 | Authority stays as columns plus two JSONB blocks (`limits`, `federation_scope`); no single `grant` document | datum-gate's single `Grant` JSONB | The columns are enforced and guard-tested today (`repo_scope`, `vault_scope`, `max_tier`, `proxy_grants`, `rate_limit_per_min`). Moving them into one document is a rewrite of every reader for a shape change. New blocks are JSONB because they are new. |
| D-04 | `is_admin` derived from `max_tier ≥ 4`, kept as a column with a check constraint | Drop `is_admin` | Thirty read sites; a constraint gives the invariant without touching them. |
| D-05 | Baseline = bearer token with a `max_tier` cap; elevated = OAuth token with a scope | A separate `agent_modes` table or a per-principal `baseline` flag | Uses two credential kinds the code already distinguishes. The ceiling is on the credential, so the same principal can hold both at once and the difference is visible in `whoami`. |
| D-06 | MCP sessions exist for counting and audit grouping only; no tool state | Stay stateless and count concurrent *requests* | "One session at a time" is a statement about a client connection, not a request. A request-level limit is a rate limit and already exists. |
| D-07 | Device authorisation grant for headless elevation | Client-credentials grant with per-agent secrets; or bearer-token exchange (RFC 8693) | Device flow puts a person in the loop, which is the brief's requirement; client-credentials does not. Token exchange would need a second trust root. |
| D-08 | Scope vocabulary is three fixed values mapping to tiers | Fine-grained scopes (`vault:write`, `repo:SCIMAC`) | Targets are already in the grant; scopes only need to set the verb ceiling. Fine-grained scopes would be a second permission language. |
| D-09 | One API process; in-memory rate windows, lockout and federation cache stay in memory | `rate_windows` table, Redis | `ratelimit.py` documents the constraint and the test to read when it changes. No deployment here runs two processes. Adding a table for a process count of one is a write per request for nothing. |
| D-10 | Policy values are environment variables in `config.py`; no `policy.yaml` | datum-gate `16`'s YAML with startup validation | Fifteen scalars. A YAML file with a schema is a second config system and a second failure mode at start. |
| D-11 | No token introspection endpoint | RFC 7662 | No upstream verifies gateway tokens; the gateway is the client of every upstream. |
| D-12 | No claim that a workspace subprocess is confined to a vault slice | datum-gate `08 §9`'s voluntary helper | The review showed the property is asserted, not built. The frozen grant on a job governs connections and attribution; saying more would be untrue. |
| D-13 | Federated upstreams use static secrets in phase 1; OAuth-to-upstream deferred | Build the gateway as an OAuth client now | Every upstream the brief names (self-hosted GitHub/Gitea MCP, SSH, an internal Drive proxy) can be given a service token. OAuth-to-upstream is a refresh-token store and a second consent flow; it attaches at the connection level later without touching guards. |
| D-14 | Teams not built; the delegation tree is the fence | datum-gate `23` teams | A sponsor's subtree already scopes what a tier-3/4 sees and edits. Teams add a labelling dimension on top and eight schema changes. Build when there is more than one organisation in the box. |
| D-15 | Memory provider not built | datum-gate `21 §3` | Independent of auth and federation; the review found unresolved contradictions in its own spec. Attaches at `05 §7`. |
| D-16 | Argument guard values use a restricted JSONPath with `join`, `const`, `[*]` | Full JSONPath library; or CEL | The four forms cover every shipped profile including `owner/repo` and `files[*].path`. A library would be a dependency and a larger attack surface in the one place untrusted arguments are parsed. |
| D-17 | Workspace tools win name clashes with federated tools | Refuse the upstream connection | An upstream can rename a tool at any time; refusing the whole connection for one clash takes every other tool down. The clash is audited and shown. |
| D-18 | `denied` becomes an `audit_log` outcome now; `mcp_call_log` is not widened | Widen both | The mirror's whole purpose was to agree row-for-row during verification. Diverging it deliberately is the recorded signal that verification is over (`09 WP7`). |
| D-19 | Scheduled jobs snapshot the owner's grant; no `system:worker` principal | datum-gate's system principal in the meet | Meeting with an empty grant produced empty grants in the corpus. The owner is the authority the schedule was created under. |
| D-20 | Inactivity auto-restricts agents, never humans | Apply to all | A person on leave should not come back to a restricted account; an agent nobody has used for a month is exactly the credential to narrow. |
| D-21 | `/enrol` is public and keyed by code, not by IP | Require a sponsor token on enrol | The registrant *has* no credential yet; the code is its credential. Per-code lockout reuses the password lockout's shape. |
| D-22 | `proxy_request` no longer requires `kind='agent'` | Keep the rule | The rule existed because accounts had no `proxy_grants` column. Authority is the grant, not the kind. |
| D-23 | The v1 UI shell is removed in the last package, not the first | Remove first | Every earlier package adds screens to v2 only; deleting v1 early would break the smoke script that packages 2–6 extend. |
| D-24 | Harness-agnostic by construction: no client-name branches in `datum_sync/`; client limitations are absorbed by gateway defaults | Per-client adapters | Three clients today and more tomorrow. A default (same-credential supersession, consent scope picker, 48-char tool names) serves all of them; an adapter serves one and rots. `12` records what each client does so the defaults are justified, not guessed. |
| D-25 | Device flow is one elevation path, not the only one; the consent page's scope picker is the other | Device flow only | Claude Code and Codex cannot drive device flow as MCP clients; both can drive PKCE with DCR. CIMD (client ID metadata documents) is a phase-2 addition for Codex and to curb DCR growth. |
| D-26 | Same-credential session supersession | Strict refusal at the limit | Claude Code reconnects without closing its old session and Datum-3.0 opens a session per call; strict refusal would lock an agent out for the idle window after every hiccup. Supersession keeps one live conversation per credential, which is what the limit is for. |
| D-27 | Tool names ≤ 48 characters | 64 or 128 | Claude Code drops tools over 64 characters and Datum-3.0 prefixes `mcp__<server>__`; 48 leaves room for a 16-character prefix. |
